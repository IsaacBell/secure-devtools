Security tools for the code you run

secure-devtools is a free, open-source security toolkit for developers who need to check code before running it. Its command-line tools check repositories, AI-generated projects and agent skills for malicious or insecure code, and check the machine you run them on.

They look for editor tasks that run when a folder opens, malicious install scripts, obfuscated payloads, persistence and screen-capture software, risky AI coding tool config, insecure AI-agent code and SSRF. They are plain shell scripts that run locally on macOS and Linux, with no signup, account or API key, and exit non-zero on findings so they drop into a dev script or CI.

npx am-i-hacked

Tools

am-i-hacked

Looks for signs of malicious code in a project before you open, install or run it. With --system, it also checks this machine for persistence, capture tools and risky AI-tool config.

npx am-i-hacked

am-i-being-recorded

Names the browser extension behind a screen-recording indicator, and what else on the machine can capture you.

npx am-i-being-recorded

secure-semgrep

Runs Semgrep with security rules for AI-agent code, MCP servers, agent hooks, shell scripts and server-side requests, plus Semgrep's own rule sets for common languages. Needs semgrep installed.

npx secure-semgrep ./src

What secure-devtools can help detect

Warning signs, not proof. The tools are not antivirus and do not look up known malware; a clean result means no warning signs were found. How they compare with npm audit, Semgrep and antivirus.

In a project, before you run it

  • Editor tasks that run when a folder opens, and download-and-run commands in editor config
  • Malicious install scripts in package.json that download, decode or eval
  • Obfuscated or encoded payloads, unusually long lines and dynamic code execution
  • Executable payloads disguised as fonts, images or other assets
  • Clipboard, keystroke or screen capture paired with an exfiltration endpoint
  • Committed .env files and tampered Yarn releases
  • Risky AI-tool config in the repository: .claude/settings.json, .mcp.json

On your machine

  • Login items and launch agents, systemd user units, autostart entries and crontab, with macOS code signatures
  • Shell startup files that pipe remote scripts, inject libraries, hijack sudo or ssh, or redirect AI API traffic
  • AI coding tool config for Claude Code, Codex, Cursor, Gemini CLI, OpenCode and Kilo Code: permission bypass, plain-text keys, unpinned MCP servers, hooks
  • Running processes that run capture scripts or scripts from staging folders
  • Browser extensions that can record your screen or a tab

In code you write or review

  • Insecure LLM and AI-agent code: hardcoded provider keys, model output passed to exec, user input in system prompts
  • MCP server command injection, tool poisoning and typosquatted tool names
  • Risky agent skills and hooks: prompt injection, exfiltration, hidden Unicode
  • Shell hazards: curl | bash, eval of downloads, IFS tampering
  • SSRF: unchecked URL fetches, automatic redirects, disabled TLS verification

am-i-hacked

The folder scan reads a project before you open, install or run anything: dynamic code execution, obfuscated payloads, editor tasks that run on folder open, payloads disguised as asset files, clipboard capture paired with an exfiltration endpoint, and .env files in the git index. --system adds the machine: login persistence and code signatures, crontab, shell startup files, AI-tool config, and running processes. It exits 1 on findings, so it drops into a dev script or CI.

npx am-i-hacked            # scan the folder you are in
npx am-i-hacked --system   # also check this machine

It reports warning signs, not proof of safety: a clean result does not prove the code or machine is safe. The am-i-hacked reference has the full list of checks, flags, exit codes and suppression syntax.

Agent skills

Instructions an AI coding agent loads when the task matches. Install all of them with npx skills add IsaacBell/secure-devtools -g, or one with --skill <name>. What each one does.

  • quarantine-review — inspect an untrusted repository without running any of it.
  • secure-skill-pull — vet a skill, plugin or MCP server from a URL without running its installer.
  • create-skill — write, check and publish an agent skill.
  • skill-publish-review — review skills before they go into a public repository.
  • ssrf-safe-fetch — validate the URL and the resolved address before a server fetches it.
  • login-item-triage — decide whether a macOS login item is legitimate or planted.
  • jujutsu — use the Jujutsu (jj) version-control system safely as an agent.

Why you can check it

  • Open source under the MIT license, maintained by Isaac Bell.
  • Plain bash with zero npm runtime dependencies: you can read every line that runs.
  • The scanners are read-only, make no network calls and collect no telemetry.
  • Bats test suites, shellcheck and shfmt in CI, plus a gitleaks secret scan, Semgrep and a security gate that runs am-i-hacked on every pull request.
  • Vulnerabilities are reported privately through GitHub security advisories.
