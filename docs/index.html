Tools

am-i-hacked

Checks a project folder before you open, install or run it — and, with --system, the machine — for supply-chain and dev-environment attack indicators.

pnpx am-i-hacked .

am-i-being-recorded

Names the browser extension behind a screen-recording indicator, and what else on the machine can capture you.

pnpx am-i-being-recorded

secure-semgrep

A thin Semgrep CLI that runs bundled AI-agent, bash and SSRF security rules plus maintained registry loadouts. Needs semgrep.

pnpx secure-semgrep ./src

am-i-hacked

The folder scan reads a project before you open, install or run anything: dynamic code execution, obfuscated payloads, editor tasks that run on folder open, payloads disguised as asset files, clipboard capture paired with an exfiltration endpoint, and .env files in the git index. --system adds the machine: login persistence and code signatures, crontab, shell startup files, AI-tool config, and running processes. It exits 1 on findings, so it drops into a dev script or CI.

pnpx am-i-hacked .          # folder scan
pnpx am-i-hacked --system   # also audit this machine

It reports warning signs, not proof of safety: a clean result does not prove the code or machine is safe. Read the am-i-hacked README for the flags and suppression syntax.

Agent skills

Install all of them with npx skills add IsaacBell/secure-devtools -g, or one with --skill <name>.

  • quarantine-review — inspect an untrusted repository without running any of it.
  • secure-skill-pull — vet a skill or plugin from a URL without running its installer.
  • create-skill — write, check and publish an agent skill.
  • skill-publish-review — review skills before they go into a public repository.
  • ssrf-safe-fetch — validate the URL and the resolved address before a server fetches it.
  • login-item-triage — the manual method behind am-i-hacked's login-item signature checks.
  • jujutsu — use the jujutsu (jj) version-control system.
